# Phase 2 design review

This review fixes the Phase 2 schema and time semantics before implementation. It keeps
the Phase 1 pipeline:

```text
Project -> Validated Project -> ResolvedTimeline -> RenderPlan -> FFmpeg arguments
```

CLI handlers mutate project intent only. They do not construct FFmpeg filters. Final
timeline positions for video clips remain derived values and are never persisted.

## Schema version 2

Phase 2 increments `version` from 1 to 2. Loading a version 1 project supplies
`speed = 1`, empty overlay/audio arrays, and writes version 2 on the next edit. No media
is probed again during migration.

The root object contains:

```json
{
  "version": 2,
  "canvas": { "width": 1080, "height": 1920, "fps": 30 },
  "media": [],
  "timeline": [],
  "text_overlays": [],
  "image_overlays": [],
  "audio_clips": []
}
```

A video clip remains in the ordered `timeline` array:

```json
{
  "id": "c1",
  "media_id": "m1",
  "source_in": 3.2,
  "source_out": 8.4,
  "speed": 1.5,
  "volume": 0.8,
  "mute": false
}
```

`source_in/source_out` are source-media seconds. Its derived final duration is
`(source_out - source_in) / speed`. Default `speed`, `volume`, and `mute` values are
omitted from JSON.

Text overlays use final timeline seconds:

```json
{
  "id": "t1",
  "text": "でもちゃんと先を読む。",
  "start": 1.0,
  "end": 4.0,
  "position": { "x": "50%", "y": "78%" },
  "font": "C:/Windows/Fonts/meiryo.ttc",
  "font_size": 64,
  "color": "white",
  "outline": { "color": "black", "width": 3 },
  "background": null,
  "opacity": 1.0
}
```

Image overlays refer to imported image media and use final timeline seconds:

```json
{
  "id": "i1",
  "media_id": "m3",
  "start": 2.0,
  "end": 6.0,
  "position": { "x": "85%", "y": "8%" },
  "width": "12%",
  "height": null,
  "opacity": 1.0
}
```

Audio clips are independent final-timeline items:

```json
{
  "id": "a1",
  "media_id": "m4",
  "start": 0.0,
  "source_in": 0.0,
  "source_out": null,
  "volume": 0.3,
  "mute": false,
  "fade_in": 0.5,
  "fade_out": 1.0
}
```

An omitted `source_out` resolves to the probed media duration. This representation can
later accept a TTS-generated WAV as ordinary imported media and an `AudioClip`; it does
not require a provider abstraction in the render path.

## Coordinates and canonical values

Positions store two normalized strings. Horizontal values accept `left`, `center`,
`right`, or `0%` through `100%`; vertical values accept `top`, `center`, `bottom`, or the
same percentage range. `--position bottom-center` is normalized to
`x = center, y = bottom`, so named positions and separate axes do not create duplicate
representations. Percentages identify the center of the overlay. Named edges apply a
safe canvas margin.

Image width and height accept positive pixel values such as `320px` or percentages such
as `15%`. If one dimension is omitted, aspect ratio is preserved; if both are omitted,
the imported size is used.

Colors accept named FFmpeg colors or hexadecimal forms after strict validation. Font
names and paths remain strings. Text content is materialized in a temporary UTF-8 file
owned by the FFmpeg adapter and passed through `drawtext=textfile=...:expansion=none`.
Font files are copied read-only to a controlled temporary name for the process lifetime.
This keeps quotes, punctuation, percent signs, backslashes, brackets, Japanese text, and
newlines out of filter syntax. Temporary paths are generated by the application, escaped
by the adapter, and deleted when the process ends.

## Time resolution and edit behavior

`ResolvedTimeline` walks ordered video clips and advances by source duration divided by
speed. Mapping a final-timeline offset back to a source clip multiplies the offset by
speed. `insert` and `remove` use this mapping when they split a sped-up clip. `trim`
continues to accept source-media times.

Text, image, and independent audio times are absolute final-timeline positions. Video
`insert`, `remove`, and `speed` do not rewrite them. This keeps BGM and overlays
independent from source clips and makes the stored times match commands and
`describe`. An item outside the current video duration remains valid but is clipped out
when rendering. Set/remove commands are the explicit way to move or delete it.

Range compilation intersects every video segment, overlay, and audio clip with the
requested final range. It subtracts the range start only in `RenderPlan`; project values
remain absolute. Source offsets account for video speed and independent audio source
ranges. Thus `play`, `frame`, `export-range`, and `render` consume the same plan.

## FFmpeg compilation

Each video segment applies `setpts=(PTS-STARTPTS)/speed`. Its own audio applies a chain of
`atempo` filters whose factors are each between 0.5 and 2.0. Accepted speed is finite and
within 0.05 through 20.0.

The base video/audio segments are concatenated first. Text and image overlays are then
composited in project array order. PNG inputs retain RGBA until the overlay step.
Independent audio inputs are trimmed, delayed to their final-timeline start, faded, and
mixed with the concatenated clip audio. Muted streams become silence before the common
mix path.

The RenderPlan contains typed positions, dimensions, styles, source slices, and relative
times. It contains no FFmpeg expressions. Only the FFmpeg adapter emits filter syntax.

## History

Each project uses `.ved/history/<project-name-and-path-hash>/undo` and `redo` beside the
project file. Before a successful edit replaces `project.json`, the validated current
Project is atomically saved to the undo stack and the redo stack is cleared. Undo first
saves the current Project to redo, atomically restores the newest undo snapshot, and
only then removes that snapshot; redo is symmetric. Each stack is limited to 100 JSON
files.

History contains project JSON only. It never copies, changes, or removes imported media.
An edit after undo clears only the controlled redo snapshot directory.

## Phase boundary

Phase 2 adds `speed`, `text-add/set/remove`, `image-add/set/remove`,
`audio-add/remove`, `volume`, `mute`, `fade-in/out`, `undo`, and `redo`. TTS providers,
TTS caching, transitions, transforms, arbitrary raw filters, hardware encoding, and
automatic subtitles remain out of scope.
